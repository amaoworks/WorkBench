# 前端界面规范

Workbench 前端使用统一的页面结构、状态反馈和交互组件。业务页面优先复用 `web/src/components/ui/`，主题样式集中在 `web/src/styles.css`。

## 组件清单

| 组件 | 用途 | 禁用场景 |
|---|---|---|
| `Button` / `ButtonLink` | 执行操作；以按钮形式进入站内页面 | 不把纯文本说明包装成按钮；站内跳转不使用裸 `<a>` |
| `Card` | 组织一组相关信息或操作 | 不为单个字段或短提示额外套卡片 |
| `PageHeader` | 展示页面标题及同行操作 | 不承载长说明；不在业务页面重复实现标题布局 |
| `ConfirmDialog` | 在破坏性操作前确认 | 不用于普通保存、导航或可立即撤销的操作 |
| `States` | 提供加载骨架 `Skeleton` | 不承载空状态或错误提示，不使用旋转图标代替页面骨架 |
| `Switch` | 切换布尔设置 | 不用于列表多选或枚举选择 |
| `Badge` | 展示紧凑状态或元信息，如已启用、已停用、只读、已保存 | 不承载操作，不用于完整句子的提示 |
| `Notice` | 展示行内状态、原因和一个相关动作 | 不用于操作成功反馈，不堆放多个无关动作；Schwab 未连接状态可同时提供设置与授权入口 |
| `Field` | 组合 Label、表单控件、元信息与关联错误 | 不用于无 Label 的按钮组或纯展示内容 |
| `EmptyState` | 展示空数据的图标、标题、可选说明和可选动作 | 不用于加载或请求失败状态 |
| `useConfirmDelete` | 管理删除目标、提交状态和关闭后的焦点恢复 | 不用于非删除操作或无需确认的操作 |

## 页面结构

- `PageHeader` 标题使用纯名词。视图切换按钮放在标题同行右侧；窄屏空间不足时允许自然换行。
- 标签页用于同一对象的不同内容视图。按钮组用于同一内容的显示模式切换，二者不混用。按钮组提供可访问名称，当前模式通过 `aria-pressed` 表达。
- 页面保留表单状态、交互反馈和渲染。接口函数、查询 hooks 与缓存刷新放在模块 `queries.ts`，响应校验和推导类型放在 `schema.ts`。

## 状态反馈

- 页面和区块加载使用 `Skeleton` 骨架。空数据使用 `EmptyState`。请求失败使用 `Notice` 的 `danger` 变体。
- 操作结果使用 toast，同一时刻最多显示 3 条。需要用户立即处理的行内状态使用 `Notice`。
- 状态卡正文按“标题 + 一句简短原因”组织，可附一个动作。在常规宽度下控制为两行内容，窄屏允许自然换行。服务端返回的动态错误保留完整可读内容，不截断，不用固定行数隐藏。
- `Notice` 通常只提供一个动作。Schwab 未连接状态可以同时提供“打开设置”和“登录 Schwab”两个相关入口。
- `Notice` 的 `warning`、`danger` 使用 `role="alert"`，`info` 使用 `role="status"`。

## 控件选型

- 布尔开关统一使用 `Switch`。复选框只用于列表多选或一组可并存选项。
- 枚举选项不超过 3 项时使用分段按钮或卡片；更多选项使用 `select`。
- 图标使用 Lucide。按钮形式的站内跳转使用 `ButtonLink`。

## 破坏性操作

- 删除操作统一使用 `ConfirmDialog` 与 `useConfirmDelete`。确认按钮文案为“确认删除”，进行态为“删除中…”。
- 取消删除，或删除失败后关闭弹窗时，将焦点还给触发按钮。
- 删除成功后，如果触发元素已经消失，将焦点移到相邻操作；没有相邻操作时移到稳定控件或区域标题。作为焦点目标的区域标题设置 `tabIndex={-1}`。

## 可达性

- 图标按钮必须提供准确的 `aria-label`。表单帮助文字和错误文字通过 `aria-describedby` 与控件关联。
- 任何操作不得只在悬停时出现；触屏可点击，键盘可聚焦。焦点样式使用 `focus-ring`，不移除可见焦点。
- 开关的触屏点击区域至少为 44×44px，轨道可保持紧凑尺寸。日期控件展示年份，并向辅助技术暴露当前值。
- 标签页支持方向键与 `Home`、`End`。弹窗支持 `Escape`、遮罩和关闭按钮，并按操作结果恢复焦点。
- 动态状态使用合适的 `role`，不要用颜色作为唯一信息来源。

## 样式

- 优先使用 Tailwind 和 `styles.css` 中的主题变量。新增颜色必须使用主题变量，并验证浅色与深色主题。
- 自定义类名按职责添加前缀：应用外壳使用 `workspace-`，表单控件使用 `studio-`，业务模块使用 `<module_id>-`。
- 不复制共享组件的结构和样式；需要新的通用行为时扩展 `components/ui/`。

## 响应式

- 最小支持宽度为 360px，不产生页面横向溢出。
- 侧栏在窄屏折叠为图标栏；标签栏允许横向滚动；表单在窄屏变为单列。
- 标题、状态原因和动态错误允许自然换行；交互控件保持可见、可点击并保留清晰焦点。

## 模块导入边界

与后端 `internal/modules/architecture_test.go` 对齐：`web/src/modules/<id>/` 不得 import 其他业务模块，也不得 import `web/src/app/`。总览、设置和应用外壳在 `features/` / `app/` 中组合各模块；模块可复用 `components/`、`shared/` 以及平台 settings 等 features 只读 hooks。该边界由 `web/eslint.config.js` 的 `no-restricted-imports` 强制检查（`npm run lint`）。

## 代码要求

- TypeScript 类型完整，不使用 `any`，不为共享组件引入重复实现或兼容层。
- JSX 单行不超过 160 个字符，超出时拆行或提取组件。
- 共享 `api` 的响应为 `unknown`；读取 JSON 字段前使用 `apiValidated` 或生产 Zod schema 校验。
- 页面交互变更验证桌面、360px 窄屏、浅色和深色主题。涉及键盘、触屏或焦点恢复时补充对应浏览器回归。
