# 前端界面规范

Workbench 前端使用统一的页面结构、状态反馈和交互组件。业务页面优先复用 `web/src/components/ui/`，主题样式集中在 `web/src/styles.css`。

## 组件清单

| 组件 | 用途 | 禁用场景 |
|---|---|---|
| `Button` / `ButtonLink` | 执行操作；以按钮形式进入站内页面 | 不把纯文本说明包装成按钮；站内跳转不使用裸 `<a>` |
| `Card` | 组织一组相关信息或操作 | 不为单个字段或短提示额外套卡片 |
| `PageHeader` | 展示页面标题、状态与操作 | 不承载长说明；不在业务页面重复实现标题布局 |
| `ConfirmDialog` | 在破坏性操作前确认 | 不用于普通保存、导航或可立即撤销的操作 |
| `States` | 提供加载骨架 `Skeleton` | 不承载空状态或错误提示，不使用旋转图标代替页面骨架 |
| `Switch` | 切换布尔设置 | 不用于列表多选或枚举选择 |
| `Badge` | 展示紧凑状态或元信息，如已启用、已停用、只读、已保存 | 不承载操作，不用于完整句子的提示 |
| `Notice` | 展示行内状态、原因和一个相关动作 | 不用于操作成功反馈，不堆放多个无关动作；Schwab 未连接状态可同时提供设置与授权入口 |
| `Field` | 组合 Label、表单控件、元信息与关联错误 | 不用于无 Label 的按钮组或纯展示内容 |
| `EmptyState` | 展示空数据的图标、标题、可选说明和可选动作 | 不用于加载或请求失败状态 |
| `useConfirmDelete` | 管理删除目标、提交状态和关闭后的焦点恢复 | 不用于非删除操作或无需确认的操作 |

## 应用外壳与导航

- 应用外壳是一条吸顶的顶部导航 `TopNav`（`web/src/app/`）：左侧 Logo，中间一级入口，右侧「问 AI」胶囊和头像菜单。没有侧栏和页脚，也没有「更多」入口。
- 一级入口依次是：总览、各已启用业务（按 Manifest Navigation 的 `order` 排序）、通知、设置。通知入口上的数字是未读数。只有「投资」带下拉菜单（图表、价格监控、持仓、订单）；券商连接在设置页。总览、待办、资讯、通知、设置都是普通链接，页面内视图用页内标签切换。`menu` 机制保留：业务下拉菜单由各模块在 `<id>.module.ts` 的 `menu` 字段声明，`menu` 为空时一级入口渲染为普通链接，外壳不内置业务菜单。
- 模块列表首次加载时，业务入口使用本地缓存显示灰色占位；没有缓存时显示骨架。已启用但尚未就绪的业务保留入口，点击显示启动或异常原因。内置模块启动中或列表请求失败时每 2 秒轮询，其他情况每 5 秒轮询。
- 下拉菜单用鼠标悬停打开，在触屏上点一下打开，用键盘时按 `ArrowDown` 或 `Alt+Enter` 打开。菜单项支持方向键、`Home`、`End`，`Escape` 关闭菜单并把焦点还给触发项。当前页面的菜单项按路径和查询参数匹配高亮，规则见 `matchesLocation`。
- 宽度不超过 960px 时，一级入口收进汉堡按钮打开的抽屉，抽屉里平铺所有入口和子菜单。宽度不超过 1180px 时隐藏快捷键提示。
- 「问 AI」胶囊和 `Ctrl+J`（macOS 上是 `⌘J`）都会打开或关闭 AI 面板。面板显示当前页面（如“总览 · 今日概况”），用户可以选择是否在消息中附带。`Ctrl+K` 不绑定任何功能。
- 页面上下文以 `{ route, label }` 发送，仅作为本轮导航提示，不拼入保存的用户文本；快捷键提示与 `aria-keyshortcuts` 按平台显示。
- 头像菜单包含 浅色/深色/跟随系统 切换和外观设置入口。主题切换与「设置 → 外观」使用同一个保存接口。
- 路由兜底：直接打开或刷新业务页面时，模块列表还在加载就显示页面骨架。之后按模块状态显示：「正在启动」并附骨架、「运行异常」、「未启用」、「页面暂不可用」或「页面不存在」，每种状态都给出一个相关操作。请求失败时显示可重试的 `Notice`。
- 非金融业务（待办、资讯、通知、设置）只使用中性主题变量，不使用行情涨跌色或交易终端风格的组件。
- 总览中同一信息只出现一次：通知只以「今日概况」磁贴出现（没有完整通知卡）；卡片不再重复磁贴已有的计数、进度和「查看全部」按钮，菜单已有的入口（打开终端、查看资讯等）不在卡片里重复。「提醒与异动」只显示价格异动和券商连接状态，夜盘只用一个指示。「配置卡片」入口在标题下方，不再有底部提示。仅首张配置卡为 large 时放到概况旁边，其他卡片保持用户配置顺序。
- `/investment` 只放图表：铺满导航下方的全部区域（`calc(100dvh - 导航高度)`），没有页头和标签，也不叠加悬浮按钮。新窗口打开、页面铺满、全屏等图表操作后续再做（见[投资模块 · 后续计划](modules/investment.md#后续计划)）。券商未连接或需要重新授权时，图表区域居中显示提示。价格监控是独立页面 `/investment/monitor`。

## 页面结构

- 只有总览使用大标题（`.overview-hero`）。其他页面（待办、资讯、通知、设置、投资各子页）不显示大标题，也不写眼眉、面包屑或副标题说明：顶栏菜单已经标明当前位置。图表页 `/investment` 没有页头。
- 其他页面统一使用 `<PageHeader title="…" description={…} action={…} />`：标题只作为 `sr-only` 的 `h1` 留给辅助技术，页面上渲染一行 `.page-toolbar`，左侧是一行实时概况（如「今天及逾期 4 项待完成 · 本周还有 2 项」「来自 3 个订阅源 · 15 篇未读」、更新时间），右侧是页面级操作（全部已读、刷新）。没有概况也没有操作时只渲染 `.page-toolbar-empty` 留出顶部间距。概况写数据，不写模块名、口号或用法说明。
- 页面内分区使用 `.sec`：`h2.sec-title` + `.sec-count`（条数）+ `.sec-action`（分区操作，右对齐）。分区标题写内容名（「今天」「全部待办」「订阅源」「历史简报」），不重复模块名。
- 券商连接、模块开关等配置只放在设置页；业务菜单（如投资下拉）只放业务视图，不放设置入口。
- 视图与范围切换使用方角标签 `.rtabs` / `.rtab`（页内用 `.rtab.sm`，条数放 `.rtab-count`），选中项使用 `--soft` 填充和 `--heading` 文字，通过 `aria-current`（链接）或 `aria-pressed`（按钮）表达；通过 `?view=`、`?tab=`、`?filter=`、`?status=` 深链。筛选条件（话题、来源、订单状态）使用 `.chip`，选中项使用 `--cta`。资讯页用 `.rtabs` 切换 文章、订阅源、关注规则、简报。
- 共享列表与卡片组件：列表行 `.trow`（`.ck` 勾选圈 / `.ic-circ` 图标圈 + `.nm` 名称与说明 + `.rt` 右侧元信息与操作）；日程卡 `.cal-grid` / `.cal`（桌面四列、1180px 及以下两列、600px 及以下横向滑动）与键值组 `.kvs`；快速输入 `.composer`（聚焦时蓝色描边）；订阅卡 `.feeds` / `.feed`（最后一张为虚线「添加」卡）；行内表单 `.inline-form`。新页面优先复用这些类，不另造结构。
- 待办页：工具栏概况 → 「今天」日程卡（今天到期及逾期，最多 8 张，卡片含优先级/分类/备注）→ 「全部待办」：视图标签（全部/今天/本周/以后/已完成，带服务端计数）、优先级与分类筛选、快速输入（截止时间、优先级、分类），列表按 已逾期/今天/本周/以后/无截止时间/已完成 分组。优先级使用单色阶徽标：高 = 实心蓝，中 = 浅蓝，低 = 中性灰，并带 `aria-label`「X优先级」。逾期使用 `warning`（橙），不使用红色。
- 资讯「文章」视图依次显示最新简报卡、「最新文章」卡片和「全部文章」列表。简报仅在未筛选且已有简报时显示；最新文章仅在未筛选且有至少 4 篇时显示，桌面为四列。列表上方提供关键词、订阅源和话题输入框，以及话题/状态快捷标签；话题输入不受快捷标签数量或文章分页限制。关键词与输入的话题点击「搜索」后生效，订阅源和快捷标签立即生效。列表按 时间 | 来源 | 标题 | 话题 排列，点击行原位展开详情。订阅源使用本地字母标记。
- 标签页用于同一对象的不同内容视图。按钮组用于同一内容的显示模式切换，二者不混用。按钮组提供可访问名称，当前模式通过 `aria-pressed` 表达。
- 页面保留表单状态、交互反馈和渲染。接口函数、查询 hooks 与缓存刷新放在模块 `queries.ts`，响应校验和推导类型放在 `schema.ts`。

## 设置页

- 设置是单页：左侧吸顶分类导航，右侧按 外观、业务模块、AI、通知推送、账户安全、数据与运行 顺序堆叠分区卡片；分区内每行左侧是名称，右侧是控件。
- 点击分类平滑滚动到对应分区，并把 `?tab=` 写入网址（`replace`）；滚动时导航高亮当前分区。`/settings?tab=modules|ai|notifications|security|appearance|data` 打开时定位到对应分区，`?module=<id>` 打开该业务的设置弹窗。
- 宽度不超过 900px 时分类导航变为吸顶的横向滚动胶囊。

## 状态反馈

- 页面和区块加载使用 `Skeleton` 骨架。空数据使用 `EmptyState`。请求失败使用 `Notice` 的 `danger` 变体。
- 操作结果使用 toast，同一时刻最多显示 3 条。需要用户立即处理的行内状态使用 `Notice`。
- 状态卡正文按“标题 + 一句简短原因”组织，可附一个动作。在常规宽度下控制为两行内容，窄屏允许自然换行。服务端返回的动态错误保留完整可读内容，不截断，不用固定行数隐藏。
- `Notice` 通常只提供一个动作。Schwab 未连接状态可以同时提供“打开设置”和“登录 Schwab”两个相关入口。
- `Notice` 的 `warning`、`danger` 使用 `role="alert"`，`info` 使用 `role="status"`。

## 控件选型

- 布尔开关统一使用 `Switch`。复选框只用于列表多选或一组可并存选项。
- 枚举选项不超过 3 项时使用分段按钮或卡片；更多选项使用 `select`。
- 图标使用 Lucide。按钮形式的站内跳转使用 `ButtonLink`。

## 破坏性操作

- 删除操作统一使用 `ConfirmDialog` 与 `useConfirmDelete`。确认按钮文案为“确认删除”，进行态为“删除中…”。
- 取消删除，或删除失败后关闭弹窗时，将焦点还给触发按钮。
- 删除成功后，如果触发元素已经消失，将焦点移到相邻操作；没有相邻操作时移到稳定控件或区域标题。作为焦点目标的区域标题设置 `tabIndex={-1}`。

## 可达性

- 图标按钮必须提供准确的 `aria-label`。表单帮助文字和错误文字通过 `aria-describedby` 与控件关联。
- 任何操作不得只在悬停时出现；触屏可点击，键盘可聚焦。焦点样式使用 `focus-ring`，不移除可见焦点。
- 开关的触屏点击区域至少为 44×44px，轨道可保持紧凑尺寸。日期控件展示年份，并向辅助技术暴露当前值。
- 标签页支持方向键与 `Home`、`End`。弹窗支持 `Escape`、遮罩和关闭按钮，并按操作结果恢复焦点。
- 动态状态使用合适的 `role`，不要用颜色作为唯一信息来源。

## 样式

- 优先使用 Tailwind 和 `styles.css` 中的主题变量。新增颜色必须使用主题变量，并验证浅色与深色主题。
- 主题由 `html.dark` 与 `html[data-palette]` 组合决定。`theme` 有 light、dark、system 三种，默认跟随系统。`palette` 默认为 `default`，即 TradingView 风格：纯白和纯黑底色，蓝色强调 `#2962ff`；另有 `claude`（暖陶）。
- 常用语义变量：`--heading`、`--card-border`、`--cta`/`--on-cta`（主按钮和选中的胶囊）、`--brand`/`--brand-soft`、`--menu-shadow`、`--radius-sm`、`--button-radius`、`--display`。
- 红绿只用于金融涨跌与盈亏；待办、资讯、通知、设置等非金融模块不用 `success`/`danger` 表达普通状态（启用、已推送、已同步用 `info` 或 `neutral`，逾期用 `warning`）。`danger` 只用于请求失败和破坏性操作。
- 蓝色 `--brand` 只用于当前导航、焦点轮廓、链接悬停、未读点和 `info` 徽标；勾选框、开关、下拉指示、空状态图标使用 `--heading`/`--soft` 黑白体系。
- 开关 `Switch` 打开时轨道为 `--cta`（黑）、滑块为 `--on-cta`；关闭为 `--chip`。勾选（`.ck.done`、`ui-checkbox`、总览待办）选中时为 `--heading` 实心。
- 徽标 `Badge` 统一为高 20px、圆角 4px、12px/600。
- 涨跌色沿用“红涨绿跌”：上涨和盈利用 `--danger`（`.pnl-up`），下跌和亏损用 `--success`（`.pnl-down`）。总览卡片使用的 `--ov-up`、`--ov-down` 遵循同一约定。
- 字体：标题使用 `--display`（Outfit，可变字重 100–900），正文使用系统中文字体。Outfit 以 woff2 随前端打包（`web/src/assets/fonts/outfit/`，附 SIL OFL 1.1 许可证），不从 CDN 加载。
- 分隔线分两级：卡片和输入框边框用 `--card-border`/`--border`，列表行之间的分隔用更浅的 `--hair`（`divide-[var(--hair)]`、`.news-row`）。
- 悬停：可点击的卡片（`a.ui-card`、`.ui-card[data-interactive]`、总览磁贴）和列表行（`.hover-rows` 的子项、通知行、资讯行）悬停时整块填充 `--soft`，只在支持悬停的设备上生效；悬停不能是发现操作的唯一途径。
- 状态统一：`.chip` 默认使用 `--chip` 填充，悬停加深；选中时添加 `.is-active` 使用 `--cta`，并通过 `aria-pressed`、`aria-selected` 或 `aria-current` 表达状态。按下时轻微加深，禁用时降低对比度并阻止操作，键盘焦点为 2px `--brand` 轮廓。`Button` 的悬停在变体中定义；按下态、`aria-pressed="true"` 的选中态（图标按钮除外）在 `styles.css` 中统一。没有可执行内容的批量操作（如没有未读时的「全部已读」）禁用并给出 `title` 说明。
- `Select` 容器最小宽度为 `min(100%, 9.5rem)`，触发器填满容器，较长选项使用省略号。
- TradingView 终端内部配色由 `internal/modules/investment/chart/theme.js` 和 `custom.css` 单独维护，外壳样式不覆盖终端内部。
- 自定义类名按职责添加前缀：应用外壳使用 `workspace-`，表单控件使用 `studio-`，业务模块使用 `<module_id>-`。
- 不复制共享组件的结构和样式；需要新的通用行为时扩展 `components/ui/`。

## 响应式

- 最小支持宽度为 360px，不产生页面横向溢出。
- 顶部导航在 960px 以下收进抽屉；标签栏和筛选标签允许横向滚动或换行；表格在窄屏横向滚动，不撑开页面；表单在窄屏变为单列。
- 标题、状态原因和动态错误允许自然换行；交互控件保持可见、可点击并保留清晰焦点。

## 模块导入边界

与后端 `internal/modules/architecture_test.go` 对齐：`web/src/modules/<id>/` 不得 import 其他业务模块，也不得 import `web/src/app/`。总览、设置和应用外壳在 `features/` / `app/` 中组合各模块；模块可复用 `components/`、`shared/` 以及平台 settings 等 features 只读 hooks。该边界由 `web/eslint.config.js` 的 `no-restricted-imports` 强制检查（`npm run lint`）。

## 代码要求

- TypeScript 类型完整，不使用 `any`，不为共享组件引入重复实现或兼容层。
- JSX 单行不超过 160 个字符，超出时拆行或提取组件。
- 共享 `api` 的响应为 `unknown`；读取 JSON 字段前使用 `apiValidated` 或生产 Zod schema 校验。
- 页面交互变更验证桌面、360px 窄屏、浅色和深色主题。涉及键盘、触屏或焦点恢复时补充对应浏览器回归。
