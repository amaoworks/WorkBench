# 资讯

页面顶部为一行概况（订阅源数、未读数、今日 AI 用量），用方角标签切换 文章、订阅源、关注规则、简报。订阅源为卡片网格（字母标记、类型/话题/条数/刷新间隔、最近刷新或错误、启用开关、刷新/编辑/删除），末尾是「添加订阅源」卡；关注规则为行列表，行尾是编辑、删除和启用开关；简报页上方是生成表单，下方是历史简报，最新一份以简报卡展示。

`/news` 管理订阅源、关注规则、资讯阅读和简报。「设置 → 业务模块 → 资讯设置」管理 AI、保留期限和定时简报；AI 服务与 Telegram 接收目标分别在平台设置中配置。

## 采集和阅读

- 来源支持 RSS 2.0、RSS 1.0 和 Atom。Google News 根据查询词生成英文美国版搜索订阅；Yahoo Finance 使用财经新闻 RSS；RSSHub 使用已有实例提供的订阅地址。各来源显示最近成功时间和抓取错误。
- 每分钟检查到期来源，各源间隔为 5–10080 分钟。请求携带 ETag、Last-Modified，网络超时为 25 秒；失败按来源持久化退避，429/503 的 `Retry-After` 可延后重试。支持单源和全部手动刷新。
- 全部刷新最多并发采集四个来源，同一来源的请求串行执行；等待可以取消。采集期间可以修改或删除来源，返回结果在写入前核对来源配置，丢弃已失效的响应。
- 单次响应上限 5 MB、500 条，文章存储最多 12000 字符的纯文本正文。正文使用订阅源提供的内容，原文链接打开原站。
- 同来源按 GUID 或链接识别条目，跨来源按去除追踪参数的规范链接合并。已知条目链接迁移到另一篇已有文章时，合并出处、已读和收藏状态。文章保留各来源；删除订阅源保留文章与阅读状态。
- 按来源、主题、关键词、未读、收藏和规则匹配筛选，使用游标分页。关键词搜索覆盖标题、正文和翻译标题。
- 资讯页工具栏显示订阅源数、未读状态和今日 AI 用量。「文章」视图未筛选时显示已有的最新简报，有至少 4 篇文章时显示最新文章卡片；下方为全部文章列表。订阅源、话题快捷标签、未读、收藏和规则匹配切换后立即生效；关键词和手动输入的话题点击「搜索」后生效。话题快捷标签最多显示 8 个，其他话题可直接输入筛选，无需先加载对应分页。列表行点击后原位展开摘要、译文、原文和 AI 分析。

## 关注规则和 AI

规则包含来源、包含关键词、排除关键词和归属主题。关键词忽略大小写；同一规则的包含词任选一个命中，排除词命中则该规则不匹配。多个规则任一命中即匹配，按名称、ID 排序的首个匹配规则决定主题。无启用规则时全部匹配。保存规则会重新计算已存文章的匹配状态，普通阅读保留未匹配文章。

自动 AI 默认关闭。开启后，每分钟最多处理三篇匹配资讯，复用 `contracts.TextGenerator`。按需分析按钮可处理任意文章，输出翻译标题、正文翻译和事实摘要。单篇 AI 使用标题及正文前 4000 字符，结果按正文、目标语言和提示词版本缓存；内容或目标语言变化后重新处理。

每日上限默认 50 次，可设为 0–1000，文章和简报共用额度；按配置时区的自然日统计。失败请求计入尝试，未启用 AI 的请求退还额度，缓存命中不消耗额度。失败可手动重试，自动任务每 15 分钟重试错误或中断的条目。

同一文章的分析串行执行，不同文章与简报可以独立生成，共享额度在事务中预留。AI 请求期间设置仍可保存；文章内容或目标语言变化后丢弃旧分析结果。简报生成完成后核对语言、时区，定时简报还核对调度设置，配置已变更时返回错误供重新生成。

## 简报和推送

手动简报选择主题、最近 1–168 小时和最多 30 条匹配资讯。AI 按主题归纳并引用来源编号，简报另存原文链接。AI 未启用或额度耗尽时生成原文标题列表，界面标明普通简报。

定时简报默认关闭，开启后按时间和时区每天生成一份，取最近 24 小时的匹配资讯。错过当天时间后补执行一次；当天已生成简报不会重复生成。简报失败状态持久化，15 分钟后再次尝试。

勾选「生成后提交推送」或手动发送简报时，通过 `NotificationService.CreateTx` 原子保存通知和简报，显式设置 `External`。Telegram 配置启用后消费该通知事件；资讯投递有效期为 24 小时。每份简报对应唯一通知，重复提交返回同一通知 ID。界面显示「推送已提交」，实际投递状态见平台通知设置。

默认保留 90 天，可设置 1–3650 天。后台按发布时间清理过期普通文章，收藏保留；简报和每日调用统计按创建日期清理。停用模块会取消正在执行的采集和 AI 请求，关闭业务接口和后续任务。

## 接口与数据

接口统一位于 `/api/modules/news/`，使用平台鉴权、CSRF 和模块门控。

| 方法 | 路径 | 用途 |
|---|---|---|
| GET / POST | `sources` | 来源列表、添加 |
| PUT / DELETE | `sources/{id}` | 修改、删除来源 |
| POST | `sources/{id}/refresh`、`refresh` | 单源、全部刷新 |
| GET / POST | `rules` | 规则列表、添加 |
| PUT / DELETE | `rules/{id}` | 修改、删除规则 |
| GET | `articles`、`articles/{id}` | 筛选分页、文章详情 |
| PATCH | `articles/{id}` | 已读、收藏 |
| POST | `articles/{id}/analyze` | 翻译摘要、重试 |
| GET / PUT | `settings` | 读取、保存设置 |
| GET | `stats` | 来源、阅读、AI、简报状态 |
| GET / POST | `digests` | 简报分页、生成 |
| POST | `digests/{id}/push` | 幂等提交推送 |

数据归属 `news_sources`、`news_articles`、`news_origins`、`news_rules`、`news_settings`、`news_digests` 和 `news_ai_usage`。SQLite、PostgreSQL 提供同版本迁移，查询由 sqlc 生成。网络及 AI 请求位于写事务外，来源、规则、阅读、分析结果和简报的对应领域事件与数据在同一事务中提交。

代码入口为 `internal/modules/news/` 和 `web/src/modules/news/`。跨端契约检查和本地替身浏览器回归见[脚本说明](../../scripts/README.md#资讯)。
