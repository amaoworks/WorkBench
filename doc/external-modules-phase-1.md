# 外部业务模块第一阶段：设计、执行计划与验收指标

> 历史设计记录：当前版本已取消通过网址添加模块，`POST /api/modules/external` 返回 404。新业务从项目代码和文件注册；以下描述中的动态接入流程不再是产品功能，已有外部模块保留管理和加载兼容。

状态：已实现（2026-09-13）。协议与主题文档已按落地代码同步；验收对照见第 9 节。

本文是供 AI agent 执行的阶段计划，描述目标行为，不代表当前代码已经具备这些能力。实现前核对工作区与本文列出的代码入口；实现后的实际接口应同步到现行架构、契约、安全和开发文档。

## 1. 目标与范围

Workbench 保留登录、应用外壳、模块目录、导航、总览及模块管理。业务既可以随核心编译，也可以作为独立 HTTP 服务接入；两种形态都在 Workbench 中管理。

本阶段的完成标准是：**同一个已经构建并运行的 Workbench，无需重新构建前后端、无需重启，就能接入一个新的外部示例模块，打开其页面、修改配置、启停业务并观察状态。外部模块离线不影响核心与其他模块。**

### 1.1 本阶段必须实现

- 兼容现有内置模块，增加外部模块协议、持久化注册、连接配置与运行时目录更新。
- 在 Workbench 设置中接入外部服务、更新连接、刷新模块描述、启用、停用及解除接入。
- 动态导航、通用外部页面容器和外部设置页入口；外部模块前端独立提供资源。
- 同源页面/API/WebSocket 代理、服务间认证、管理接口与业务接口分离。
- 持久化期望启停状态，显示实际确认状态、健康状态和错误，失败后自动重试。
- 将现有投资模块的特殊路由注册与连接清理改为通用模块契约。
- 一个独立进程运行的最小示例模块，以及验证完整接入流程的自动化测试。

### 1.2 留给后续阶段

- 投资应用整体迁出、投资数据库拆分与旧数据迁移。
- 富途、嘉信分别变为独立服务，以及新增券商业务功能。
- Docker 容器安装、启动、停止、升级、镜像市场和部署代理。
- 外部模块注册 AI Tool、Job、事件消费者和自定义总览 Widget。现有内置能力继续工作。
- 通用 JSON Schema 表单生成器、远程 React 组件加载及不可信插件隔离。

本阶段采用模块自带的设置页，满足统一入口与独立发布。后续可以增加 schema 表单模式。本阶段不重写调度器或消息系统。

## 3. 设计决策

### 3.1 内置与外部模块并存

统一对前端返回模块描述，增加 `kind: builtin | external`。现有 `enabled` 字段保留，明确表示用户期望状态；实际运行状态使用独立字段。

内置模块继续使用 Go 注册器和原有迁移。外部模块通过 JSON/HTTP 协议接入，拥有自己的业务数据、迁移和后台任务；Workbench 不打开外部模块数据库，不执行其 SQL 或 Go 代码。

外部模块的运行时新增、删除不改写正在使用的静态路由表：预先挂载通用路由，按模块 ID 查询注册表并分发。目录使用锁或不可变快照，禁止向请求线程暴露正在修改的 slice/map。

模块 ID 全局唯一，沿用现有 ID 校验，禁止覆盖 `core`、内置模块或其他外部模块。外部协议使用独立的 `protocolVersion`，不混同现有 Go `contractVersion` 或业务 `version`。

### 3.2 模块管理和容器管理

| 用户操作 | 本阶段语义 |
|---|---|
| 接入服务 | 验证用户提供的地址、服务凭据和描述，保存注册信息；初始状态为停用 |
| 启用 | 保存期望状态，通知模块恢复约定的业务活动，收到确认后开放业务请求 |
| 停用 | 立即关闭宿主业务入口与代理长连接，通知模块暂停业务任务和订阅；保留管理接口 |
| 修改设置 | 通过管理通道读取、校验并保存业务配置，停用时仍可操作 |
| 解除接入 | 删除宿主的外部连接、凭据和目录记录，不删除外部数据或停止容器 |

解除接入仅允许在期望状态已停用且远端已确认停用后执行。离线模块可以先保存停用意图，待恢复确认后解除；强制解除不属于本阶段。更新连接后不得自动启用业务。

业务停用不能撤销已经提交的外部操作，例如已发送的订单。模块应停止新的业务活动并按约定完成或取消在途任务，准确上报状态。

### 3.3 前端独立发布

- 外部模块自己提供业务页和设置页，Workbench 用通用 iframe 容器嵌入。
- 第一阶段只接入用户管理的可信服务。同源 iframe 与宿主共享浏览器信任边界，不宣称它能隔离恶意模块脚本。
- 模块资源和请求必须适配下述挂载前缀；不以重写任意 HTML/JavaScript 作为兼容方案。
- 宿主传入模块 ID、业务 API 前缀、管理 API 前缀和当前主题；可通过查询参数初始化。
- 主题变化使用最小 `postMessage` 消息；双方校验 `event.origin` 与 `event.source`，不通过消息或 URL 传递服务密钥。
- 设置页不得因业务停用而被卸载或拒绝访问。远端离线时显示错误，宿主仍可编辑服务地址、凭据及重试。
- 自定义图标第一阶段使用宿主内置图标 ID，未知值使用默认图标。

## 4. 外部模块协议 v1

以下路径和字段作为本阶段实现基线。确需调整时，同步修改本文、协议类型、示例与测试，保持只有一套定义。

### 4.1 注册信息

用户在 Workbench 中填写 `baseUrl`、`serviceToken` 和可选的 `allowNonLocal`。`baseUrl` 第一阶段只允许 HTTP/HTTPS origin，不允许用户名密码、路径前缀、查询或片段。默认只连接 loopback；Compose 服务名或其他地址需要显式允许非本机连接。

同一个外部服务实例在第一阶段只由一个 Workbench 注册管理。不同宿主共同管理同一实例不在协议保证范围内。

Workbench 使用专用服务凭据访问下表接口；外部服务负责验证。首次接入必须成功读取并验证 manifest，再保存记录和停用意图。数据库保存失败不得留下已发布的内存目录。

### 4.2 远端管理接口

| 方法与路径 | 语义 |
|---|---|
| `GET /_workbench/manifest` | 返回模块身份、协议版本、页面及设置入口 |
| `GET /_workbench/status` | 返回实例 ID、已应用的控制代数、实际启停状态及健康信息 |
| `PUT /_workbench/state` | 幂等应用 `{ registrationId, generation, enabled }`，返回应用结果 |
| `GET /_workbench/config` | 返回模块业务配置的脱敏视图 |
| `PUT /_workbench/config` | 模块校验并保存业务配置，返回脱敏结果或结构化错误 |

管理接口在业务停用时保持可用。控制代数规则见第 6 节；`status`、`state` 返回值应包含 `registrationId`、`generation`、`enabled`，宿主只接受匹配当前连接的结果。

配置 JSON 的业务结构由模块定义。未提交的密钥字段表示保留，清空使用模块明确约定的操作；更换目标地址时不能自动把旧密钥发送给新目标。模块负责配置校验，宿主限制请求大小且不记录配置正文。

Manifest 示例：

```json
{
  "id": "demo_external",
  "name": "外部示例",
  "version": "0.1.0",
  "protocolVersion": 1,
  "icon": "module.default",
  "capabilities": ["pages", "settings", "lifecycle"],
  "pages": [
    {
      "key": "demo_external.overview",
      "label": "外部示例",
      "entry": "/ui/index.html",
      "order": 30
    }
  ],
  "settings": { "entry": "/settings/index.html" }
}
```

`lifecycle` 为必需能力。`pages` 和 `settings` 可以省略，但声明后对应字段和接口必须存在。页面 key 必须归属模块且唯一；入口必须是对应目录下的相对本站路径。第一阶段仅接受上述能力，其他能力返回明确的不支持错误。

宿主生成导航 URL `/apps/{id}/{pageName}`，其中 `pageName` 是去掉 `{id}.` 前缀的页面 key。禁止 manifest 自由占用宿主 `/settings`、`/api/auth` 等路径。

初始接入遇到不支持的 `protocolVersion` 时拒绝保存。已接入模块刷新后不兼容，保留最后有效描述与连接配置，标记 `incompatible` 并关闭业务代理；不能把无效描述覆盖进有效目录。

### 4.3 Workbench 管理 API

| 方法与路径 | 语义 |
|---|---|
| `GET /api/modules` | 合并内置与外部目录，返回缓存状态，不同步等待远端探测 |
| `POST /api/modules/external` | 验证连接并接入，成功返回 201 和模块状态 |
| `PUT /api/modules/{id}/connection` | 更新外部连接；要求期望状态为停用，校验 manifest ID 一致 |
| `POST /api/modules/{id}/refresh` | 有界刷新 manifest 和状态 |
| `PUT /api/modules/{id}/enabled` | 复用原入口；外部模块返回 200 表示已确认，202 表示意图已保存、等待确认 |
| `GET /api/modules/{id}/status` | 返回已缓存的状态及最后检查时间 |
| `GET /api/modules/{id}/config` | 经认证的远端配置读取 |
| `PUT /api/modules/{id}/config` | 经认证与 CSRF 校验的远端配置保存 |
| `DELETE /api/modules/external/{id}` | 解除外部接入，受第 3.2 节条件约束 |

所有管理入口遵循现有登录、Host、Origin、CSRF 和结构化错误约定。外部专用操作作用于内置模块时返回明确错误。

连接更新先验证候选配置，成功后原子替换并使旧请求、旧 WebSocket 与旧状态响应失效。更换 origin 必须重新提供服务凭据。旧端点失联时允许修正连接，但保留“旧端点未确认停用”的提示，不把新端点的确认当作旧端点已停止。

### 4.4 通用访问代理

| 宿主路径 | 远端路径 | 门控 |
|---|---|---|
| `/modules/{id}/ui/*` | `/ui/*` | 已登录、已启用且远端确认可用 |
| `/modules/{id}/settings/*` | `/settings/*` | 已登录，允许业务停用 |
| `/api/modules/{id}/proxy/*` | `/api/*` | 已登录、已启用且远端确认可用；支持 WebSocket |
| 上表的配置管理 API | `/_workbench/config` | 已登录，允许业务停用 |

外部 settings 静态路径仅接受 GET/HEAD，写配置必须走配置管理 API。业务代理不得通过路径穿越或编码变体访问 `/_workbench/*`、设置管理路径或其他模块。

业务放行条件为期望启用、当前连接的当前代数已确认启用，且服务可达、协议兼容。`degraded` 可继续打开模块页面，由模块显示未授权等依赖问题；不能因为某个业务依赖未就绪就阻断修复问题所需的设置入口。

代理清除浏览器 Cookie、客户端 Authorization、伪造身份头与不可信转发头，再注入该模块专用服务凭据。屏蔽上游 `Set-Cookie`，校验并仅重写允许挂载范围内的重定向；服务端管理请求不跟随重定向。

地址校验同时覆盖连接时解析结果；未允许非本机地址时，所有实际拨号地址都必须是 loopback。代理不能接受用户提供的任意目标 URL。

WebSocket 升级前执行认证、Origin 与业务状态校验；升级后纳入按模块归属的连接集合，在停用、换连接、解除接入或宿主退出时关闭。普通 HTTP 超时不能误用为已升级长连接的总时限。

第一阶段不开放外部模块声明匿名回调路径。现有内置 Schwab OAuth 回调通过通用内置路由契约保留；投资迁出时再扩展外部回调协议。

## 5. 持久化与信息归属

继续使用现有 `modules` 记录统一身份和期望开关，增加来源类型；外部明细以独立表保存，避免内置启动同步改变外部身份。具体列名可随现有 sqlc 风格调整，但以下语义必须持久化：

- 模块 ID、来源类型、服务 origin、非本机许可、服务凭据及其是否已配置。
- 最后有效 manifest、协议版本、注册 ID、连接修订号。
- 期望启停状态、控制代数、最后确认的代数与启停状态。
- 最后检查时间、最后成功时间、脱敏错误和上次观察到的实例 ID。

运行中的请求和 socket 保留在内存。宿主重启后上次健康状态只能作为历史显示，实际状态先设为未知；远端重新确认前不得仅凭旧健康记录开放业务代理。

宿主保存的是服务接入凭据；券商密钥、OAuth token 和行情缓存仍属于业务。本阶段不新增业务数据到核心表，也不改变已有投资表归属。

服务凭据沿用现有数据库文件权限与备份边界，禁止 API 回显、日志输出或写入 manifest。文档明确当前数据库未加密，不宣称新增字段获得额外加密保护。

新增迁移必须兼容已有数据库，保留内置模块 enabled 值和总览布局。SQL 经 sqlc 生成，禁止手改生成文件。核心备份只覆盖宿主注册数据，不表示已经备份外部模块业务数据。

## 6. 启停、故障和并发规则

### 6.1 分开表示三类状态

- `enabled`：用户期望开关，数据库保存成功后才更新。
- `observedEnabled`：远端最近确认的实际开关，可为未知；附带确认代数和时间。
- `health`：`unknown | ready | degraded | offline | incompatible`，与开关独立。业务依赖未授权可为 degraded，不等于服务进程离线。

例如期望停用、远端不可达时，显示“业务入口已关闭，等待服务确认停用”。启用未确认时显示“正在启用”，不能提前显示成功。

### 6.2 状态应用

1. 每次期望状态改变，事务保存状态并递增 `generation`。同一注册身份的代数跨宿主重启持续递增。
2. 停用意图保存后立即关闭宿主业务门控并清理现有代理连接，然后调用远端。启用需等当前代数得到确认再开放。
3. 远端幂等处理同代数、同载荷的重复请求，拒绝旧代数或同代数不同载荷，持久化已应用状态后返回确认。
4. 宿主在请求上下文中保存连接修订号用于响应比对；旧连接、旧代数或旧实例的晚到响应不得覆盖当前状态。
5. 每模块串行控制，有界后台重试，不持有全局注册表锁执行网络操作。恢复连接、宿主重启、远端重启后重新协调期望状态。
6. 远端初始启动默认暂停业务，加载自身持久化状态并接受协调。新注册身份替换旧身份前，要求服务处于停用状态且通过专用凭据认证。

远端实例每次进程启动使用新的 `instanceId`。持久化的已应用代数不能替代实际运行状态；重启后重放同代数命令也要确保任务/订阅恢复到期望状态，不能只返回历史成功响应。

本阶段不实现“宿主失联就自动停业务”的租约。宿主无法联系远端时，只保证宿主入口关闭并保存重试意图，不能保证远端任务已经停止；必须在界面和文档中如实表达。

### 6.3 有界等待与资源清理

默认控制/探测请求超时 5 秒，周期检查间隔 30 秒，失败重试使用退避，间隔上限 30 秒；参数集中定义并可在测试中注入。并发探测默认最多 4 个，避免离线模块占满资源。

`GET /api/modules` 不等待这些请求。正常注册、配置变更及启停动作结束后立即刷新前端缓存；模块管理页轮询缓存状态，默认间隔 5 秒。

宿主关闭有总超时，释放自身 HTTP/WS、后台探测和重试任务，不把“宿主退出”持久化为用户停用外部业务。删除注册后停止其后台任务，不允许旧任务重新发布目录或状态。

## 7. 内置模块适配

将投资的路由和生命周期特殊处理抽象为可选的标准契约，建议集中在 `internal/contracts`：

- `ModuleLifecycle`：应用启停、关闭本进程资源；无后台资源的模块可以不实现。
- `ModuleRouteProvider`：声明静态资源、受保护业务入口及明确的公共回调入口。
- 公共回调与登录后的业务/管理入口分开标注，禁止通过普通业务注册自动获得匿名访问。

App 只负责构造内置模块并遍历这些契约。`investment.New(...)` 可以保留在装配处；路由、停用、Shutdown 路径不得再检查 `id == "investment"`，也不得保存专供这些分支使用的投资实例字段。

投资实现生命周期时，停用仍关闭 Schwab Streamer 与 Futu gateway；退出释放所有连接。普通业务请求、Job、AI Tool、事件消费者保持现有门控语义。保留 `/oauth/schwab`、`/investment/terminal`、`/charting_library/*` 及现有业务 API 的兼容行为。
