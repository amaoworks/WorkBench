# 用户与权限

## 启用多用户

多用户使用密码模式，外部访问通过 HTTPS 反向代理：

```sh
./workbench -auth password -listen 127.0.0.1:8080
```

初始管理员用户名为 `admin`。初始密码由 `WORKBENCH_PASSWORD` 提供，未提供时在首次初始化日志中输出一次。首次登录后修改密码，再在「后台设置 → 用户管理」创建用户。

本机免登录模式只允许一个有效的原始管理员。已有其他账号时，即使账号已禁用，也不能以本机免登录模式启动。该模式不允许创建用户。

## 权限

| 范围 | 管理员 | 普通用户 |
|---|---|---|
| 创建、禁用用户，调整角色，重置密码 | 可管理 | 不可管理 |
| 模块启停、AI 服务、日志、备份、签名密钥 | 可管理 | 不可管理 |
| 富途登录、OpenD、夜盘总开关 | 可管理 | 仅使用行情 |
| Schwab 应用 Key、Secret、回调 | 可管理 | 不可管理 |
| Schwab 授权、账户、持仓、订单与交易 | 仅本人 | 仅本人 |
| 待办、Wallos、资讯、自选、监控、净值 | 仅本人 | 仅本人 |
| AI 会话、通知、设备、外观和总览布局 | 仅本人 | 仅本人 |
| 历史外部模块页面、配置和 API 代理 | 可访问 | 不可访问 |

「个人设置」（`/settings`）向所有用户开放，管理员也在此管理本人的业务配置、通知接收、密码和设备。「后台设置」（`/admin/settings`）仅管理员可见并受路由保护，管理用户、全局业务启停、共享服务和数据与运行。具体分区见[配置与运行](configuration.md#设置页面)。Telegram Bot 在后台通知服务配置，用户接收目标在后台用户管理的「通知目标」分配，个人设置只提供本人的接收开关、目标展示、测试和状态。

管理员角色不绕过个人业务数据归属。管理员可以重置用户密码，因此管理员账号仍是高信任账号。拥有服务器或数据库访问权限的运维人员能读取数据库内容；应用没有对数据另行加密。

用户初始密码及重置后的密码要求首次修改。禁用用户会撤销其登录；重新启用不会恢复旧会话。最后一个有效管理员不能被禁用或降级。账号不提供硬删除。

## 券商连接

Schwab 应用配置在「后台设置 → 业务管理 → 投资」（`/admin/settings?tab=modules&module=investment`）维护，用户授权在「个人设置 → 业务 → 投资」（`/settings?tab=modules&module=investment`）管理；管理员同样单独完成本人授权。两者分开保存。Schwab 行情、账户、订单及交易使用当前用户自己的 OAuth 令牌，不借用管理员的令牌；仅填写 App Key / Secret 不会取得行情权限。OAuth state 关联发起用户，公共回调不依赖回调浏览器当前登录的账号。应用配置变更使受影响的旧授权和连接失效。

同一应用供多个用户授权使用，需要取得相应 Schwab 应用许可。若券商应用不允许该使用方式，不应开放该部署给其他用户。

富途共用一套登录、OpenD 和上游行情缓存，服务开关、登录和夜盘总开关在后台投资设置管理。自选、图表偏好和订阅控制归个人；释放一个连接的订阅不会释放其他连接仍在使用的上游订阅。

| 当前用户状态 | 常规及扩展行情 | 夜盘行情 | 账户、持仓、订单与交易 |
|---|---|---|---|
| 未绑定 Schwab | 使用可用的共享富途服务 | 富途，需开启夜盘且标的支持 | 不可用 |
| 本人 Schwab 授权有效 | 本人的 Schwab，不重复使用富途主行情 | 富途，需开启夜盘且标的支持 | 仅本人 |
| 本人 Schwab 授权失效 | 使用可用的共享富途服务，只读看盘 | 富途，需开启夜盘且标的支持 | 重新授权前不可用 |

行情接口仍要求工作台身份，富途不会开放匿名访问，也不会共享任何用户的私人持仓。富途主行情不依赖夜盘开关；支持范围为美股和 ETF，实际行情权限、历史额度和标的取决于富途账号与 OpenD 状态，保存凭据不保证实时可用。部署方须确认行情许可允许该部署下的多用户使用。

总览行情卡可显示本人的富途自选行情及数据源；资产快照仍依赖本人 Schwab 授权。价格监控继续只使用本人的 Schwab 授权，富途不参与后台预警。

## 升级

1. 停止用户操作并备份工作空间。PostgreSQL 使用数据库备份工具。
2. 启动新版本，执行平台及各模块迁移。
3. 原单用户身份迁为 `admin`，保留密码及首次改密状态。
4. 原有个人业务数据、Schwab 授权、通知、对话和偏好归原管理员；富途配置继续共享。
5. 历史网页、设备及 WebView 登录失效，所有客户端重新登录。旧客户端须更新为用户名和密码登录。
6. 验证原管理员数据后再创建新用户。新用户默认没有其他用户的个人数据。

回退旧版本使用升级前的完整备份，不将多用户数据合并回单用户数据库。

## 开发约定

- `contracts.Principal` 只由可信认证或后台调用建立。客户端和 AI 参数中的用户 ID 不能决定执行身份。
- 私有服务使用 `RequireUserID`；缺失身份返回错误，不回退到 `owner` 或查询全部用户。
- 所有详情、分页、统计、更新、删除、关联和幂等操作限定用户。管理员不绕过该条件。
- 后台任务通过注入的 `UserDirectory` 枚举有效用户，每项工作使用明确的用户身份。
- 持久化事件保存用户归属，投递时恢复身份；通知明确收件人，SSE 和外部推送按收件人投递。
- 前端身份变化时清理请求、缓存和连接；个人浏览器存储使用用户命名空间。浏览器请求以 `X-Workbench-User` 固定发起身份，长连接以 `workbenchUser` 查询参数固定身份；服务端只将其作为一致性检查，不用它认证或选择用户。不匹配时返回 `409 account_changed`。独立投资终端同样固定身份，切换账号后停止请求、丢弃待保存草稿并关闭连接，不更新身份后自动重试。
